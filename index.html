Implication technique Data Science · Machine Learning · Turn.io

Architecture cible d'ARED Edu : la couche messaging (messages entrants et sortants WhatsApp) est assurée par Turn.io. La logique pédagogique, l'analyse et l'IA reposent sur une couche Data Science / ML côté serveur.

Inbound & outbound WhatsApp → Turn.io · Intelligence pédagogique → Data Science + ML

Turn.io reçoit les messages (inbound via webhooks) et envoie les réponses (outbound via /v1/messages). ARED Edu traite le contenu, consulte le graphe de connaissances et appelle les modèles ML si besoin.

📥📤 Turn.io — Messaging (Inbound / Outbound)

  • Inbound — messages entrants (texte, audio, image, boutons) reçus via webhooks WhatsApp (whatsapp subscription).[T1]
  • Outbound — envoi synchrone via POST /v1/messages : texte, médias, templates, messages interactifs (listes, boutons).[T2]
  • Statuts de livraison — notifications outbound (delivered, read, failed) pour le suivi des envois.[T1]
  • Lien inbound ↔ outbound — header X-Turn-In-Reply-To pour tracer quelle réponse répond à quel message (audit, analytics, entraînement ML).[T3]
  • Aligné WhatsApp Business API — Turn.io expose un sous-ensemble compatible Meta ; ARED Edu n'appelle pas Meta directement.

📊 Data Science — logique & données

  • Graphe de connaissances — source unique : concepts, prérequis, statuts (maîtrisé / en cours / à renforcer) par matière et niveau.
  • Séquençage curriculum — leçons Maths (semaine · jour · n°) et séquence Français dérivées du graphe.
  • Analytics classe — agrégation des scores élèves → % de maîtrise par nœud, détection des lacunes.
  • Remontées terrain — structuration des retours d'information (guides, apprentissage, incidents) pour amélioration continue.
  • Profils enseignants — code ENS, classes, matières, historique d'usage (tables relationnelles / entrepôt).
  • Tableaux de bord — indicateurs pédagogiques : progression, concepts faibles, usage des modules.

🤖 Machine Learning — intelligence conversationnelle

  • NLP / Question libre — compréhension des questions enseignant (texte) → routage vers le bon module (guide, exercice, traduction…).
  • Speech-to-Text — transcription des notes vocales 🎤 (audio WhatsApp → texte) avant traitement NLP.
  • RAG sur guides — Retrieval-Augmented Generation : questions sur les guides pédagogiques → réponses ancrées dans le contenu officiel.
  • Génération d'exercices — modèle conditionné par leçon, niveau, matière et graphe de prérequis.
  • Traduction FR ↔ langues locales — modèles multilingues (Pulaar, Wolof, Sérère, Mandinka, Soninké) avec fallback « mot le plus proche ».
  • Recommandation / remédiation — suggestion de concepts à retravailler à partir des scores agrégés (classification + règles graphe).

⚙️ Pipeline technique (résumé)

  1. 1. Message WhatsApp entrant → webhook Turn.io → ARED Edu API
  2. 2. Identification utilisateur (code ENS / rôle élève) + état de session
  3. 3. Si menu structuré → machine à états (flow UX) ; si texte/voix libre → NLP + ML
  4. 4. Consultation graphe de connaissances + données classe (Data Science)
  5. 5. Génération réponse (règles + modèles ML si nécessaire)
  6. 6. Réponse outbound via Turn.io /v1/messages (texte, image, liste interactive)
  7. 7. Logging événements → entrepôt données → ré-entraînement / analytics

Exigences Faisabilité — Turn.io · WhatsApp · DS / ML

ARED Edu passe par Turn.io pour tout le messaging (inbound webhooks, outbound /v1/messages). La logique pédagogique, le graphe de connaissances et l'IA tournent côté serveur — hors limites WhatsApp. Ce qui est faisable tel quel, et ce qui demande un ajustement.

WhatsApp ⇄ Turn.io (inbound / outbound) → ARED Edu API → Data Science + ML

✅ Faisable via Turn.io (messaging)

  • Inbound — texte, audio, image, boutons interactifs reçus par webhook (whatsapp).[T1]
  • Outbound synchrone — réponses via POST /v1/messages : texte, médias, listes, boutons.[T2]
  • Menus & navigation — listes interactives (≤ 10 lignes) et boutons de réponse (≤ 3) : MENU, classes, matières, modules.[1][T2]
  • QCM / choix unique — une réponse parmi N options : boutons (≤ 3) ou liste (≤ 10) ; idéal pour exercices élève et menus.[1]
  • Notes vocales — réception inbound (audio / voice) et renvoi outbound.[2][T1]
  • Images pédagogiques — flashcards, badges, exercices visuels (JPEG / PNG uploadés puis envoyés).[2][T2]
  • Statuts de livraison — sent, delivered, read, failed pour tracer les envois élèves.[T1]
  • Traçabilité inbound ↔ outbound — header X-Turn-In-Reply-To pour lier réponse et message d'origine.[T3]

✅ Faisable côté serveur (hors Turn.io)

  • Graphe de connaissances — prérequis, maîtrise classe, séquençage leçons : logique Data Science, aucune limite messaging.
  • Question libre & voix → IA — NLP + STT + RAG guides : traitement backend après réception du webhook.
  • Génération d'exercices — modèles ML conditionnés par leçon, niveau et graphe.
  • Traduction FR ↔ langues locales — modèles multilingues + fallback côté ML.
  • Analytics & remédiation — agrégation scores, détection lacunes, recommandations.
  • Session & machine à états — code ENS, classes, écran courant : état stocké en base, pas dans Turn.io.
  • Retours terrain — structuration et stockage des incidents signalés par l'enseignant.

🔘 QCM & sélection multiple — ce que WhatsApp autorise

Meta précise : « Users cannot select more than one option at the same time from a list or button message ».[1] Le prototype web permet la multi-sélection (☑️ classes / matières) ; sur WhatsApp, il faut adapter.

✅ QCM — une réponse parmi plusieurs

  • Autorisé nativement — format standard des messages interactifs WhatsApp.
  • Boutons de réponse — max 3 options par message (ex. « Oui / Non / MENU »).
  • Listes interactives — max 10 lignes (ex. catégories d'exercices, modules du MENU).
  • Exercices élève — réponse par chiffre, emoji ou bouton ; une question à la fois.
  • Navigation enseignant — tous les choix « une option parmi N » du parcours.

⚠️ Sélection multiple — plusieurs cases en même temps

  • Non natif — pas de cases à cocher simultanées dans une liste ou des boutons classiques.[1]
  • Onboarding classes (CI→CM2) — le prototype ☑️ multi-classe doit être adapté.
  • Contournement recommandé — boutons toggle + « ✅ Valider (N classes) » : chaque clic met à jour l'état serveur ; paginer par groupes de 3 (limite boutons).
  • Matières (Maths + Français) — simple : 2 toggles + Valider (tenable en un message).
  • Alternative texte — « Écrivez vos classes : CI, CE1, CM2 » → parsing NLP côté serveur.
  • Alternative avancée — WhatsApp Flows avec CheckboxGroup pour vraie multi-sélection (plus lourd à mettre en place ; non supporté sur WhatsApp Web).[6]

⚠️ À ajuster — contraintes WhatsApp (via Turn.io)

  • SVG non supporté — convertir les visuels du prototype en PNG / JPG avant upload média Turn.io.[2]
  • Push proactif élève (hors fenêtre 24 h) — obligatoire via templates approuvés Meta ; les listes/boutons interactifs ne marchent que dans la fenêtre de service.[3][4]
  • Plafond templates — nouveau numéro limité à ~1 000 destinataires/jour ; montée en charge progressive selon tiers WhatsApp.[T2]
  • Graphe visuel interactif — non cliquable dans le chat → envoyer en image + menus texte pour la navigation.
  • Médias outbound — upload préalable via l'API média Turn.io (id requis) ; pas d'envoi direct de SVG.[T2]

⚠️ À ajuster — contraintes Turn.io & architecture

  • Webhook ≤ 5 secondes — Turn.io coupe au-delà ; STT / LLM / génération doivent être asynchrones : acquitter vite, traiter en arrière-plan, répondre ensuite.[T1]
  • Pas de file d'attente outbound — si /v1/messages échoue, le message n'est pas mis en queue ; prévoir retry côté ARED Edu.[T2]
  • Rate limiting — limite par numéro WhatsApp ; dimensionner les envois massifs (classe entière) et espacer si besoin.[T2]
  • Dédoublonnage webhook — vérifier l'unicité du message id pour éviter les doubles traitements (retries Turn.io).[T1]
  • Payloads boutons — mapper les reply.id des listes/boutons vers la machine à états ARED Edu (équivalent des clics du prototype).
  • Sécurité webhooks — valider la signature X-Turn-Hook-Signature (HMAC SHA256) sur chaque événement entrant.[T1]
  • Journeys Turn.io — optionnels ; ARED Edu peut tout orchestrer via API custom plutôt que les automations Turn.io natives.
≈ 95 % intégrable — Turn.io couvre inbound/outbound ; le reste = ajustements (async ML, PNG, templates, état session), pas des blocages.

Référentiel des fonctionnalités d'ARED Edu : à quelle question chacune répond, en bref. Cliquez pour déplier.

👩‍🏫 Enseignant

Onboarding — classes & matières
Répond à : Configuration initiale après connexion par code. Sélection des classes (CI→CM2) et matières (Maths, Français). Prototype : multi-sélection ☑️. WhatsApp : à adapter (toggle + Valider ou saisie libre) — voir Exigences.
MENU principal
Répond à : Hub central avec 5 options : Guide et enseignement, Apprentissage continu, Retours d'information, Profil, Fermer la session.
Sub Menu 1 — Exercices / Guides
Répond à : Choix entre le module Exercices (saisie n° de leçon → résultat → boucle ou catégories) et le module Guides/Leçon (unité → niveau → Q&A).
Module Exercices
Répond à : Entrée du numéro de leçon, affichage de l'exercice, option « autre exercice même thème » ou liste des catégories.
Module Guides/Leçon
Répond à : Unité de terrain (Maths/Français) → niveau → question libre/voix → réponse du guide → nouvelle recherche ou MENU.
Module Traduction (Apprentissage continu)
Répond à : Groupes de langues locales → bienvenue → traduire un mot (FR↔Local) → saisie → traduction → boucle.
Module Retours d'information
Répond à : Sujet (guides, apprentissage, autre) → saisie incident → importance → info supplémentaire → confirmation → MENU.
Profil & fermer session
Répond à : Modifier classes/matières/langue. Fermer la session déconnecte et renvoie vers la connexion par code.
Question libre & voix 🎤
Répond à : Saisie contextuelle selon l'écran (n° leçon, question guide, mot à traduire, incident…) ou question générale avec réponse IA.

🧒 Élève

Réception d'exercice
Répond à : « Qu'est-ce que je dois faire ? » L'exercice est poussé par l'enseignant ; le parent ouvre, l'enfant participe (session ~5 min).
Questions audio + image
Répond à : « Comment répondre quand je ne lis pas encore ? » Consigne en voix, support en image, réponse par chiffre/emoji. Une question à la fois.
Réessai bienveillant
Répond à : « Et si je me trompe ? » Jamais de sanction : indice visuel et nouvelle tentative.
Récompense & série
Répond à : « Pourquoi revenir ? » Badge image + série (streak) pour la motivation.
Remontée des scores
Répond à : « Que deviennent mes réponses ? » Les scores remontent automatiquement vers les analyses de l'enseignant.

🕸️ Système

Graphe de connaissances
Répond à : « Sur quoi se base le contenu ? » Concepts + prérequis par matière. Source unique dont dérivent leçon, exercices, planning et remédiation.
Image d'abord 🖼️
Répond à : « Comment limiter le texte ? » Flashcards, cartes à compter et badges (SVG/PNG légers) pour les jeunes élèves et le faible débit.
Boucle pédagogique
Répond à : « Comment tout se connecte ? » Enseignant → élève → analyses → remédiation → élève. L'élève ferme la boucle de l'enseignant.
Un numéro, plusieurs rôles
Répond à : « Faut-il plusieurs apps ? » Non : le rôle stocké (enseignant / parent-élève) change le comportement du bot. Tout sur WhatsApp.

📋 Intégration WhatsApp · Turn.io

Répond à : « Est-ce intégrable ? » ≈ 95 %. Turn.io gère inbound (webhooks) et outbound (/v1/messages) : menus, voix, images, statuts. DS/ML côté serveur : graphe, IA, exercices, traduction. Ajustements : PNG au lieu de SVG, templates pour le push hors 24 h, webhook répondu en < 5 s (ML async), état session en base. Détails dans Exigences et Implication technique.
QCM vs sélection multiple
Répond à : « Le multiple choice est-il permis ? » Oui pour un QCM (une réponse parmi 2–10 options via boutons ≤ 3 ou liste ≤ 10). Non pour cocher plusieurs classes en même temps comme dans le prototype — adapter avec toggles paginés, saisie libre ou WhatsApp Flows. Voir Exigences → QCM & sélection multiple.
